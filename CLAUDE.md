# askmystuff

A `CLAUDE.md` in a parent directory of this checkout may describe an unrelated project (e-commerce, SQLite, TypeScript). Ignore it here.

Read before working:

- `docs/DESIGN.md`: what askmystuff does, its architecture, how it is evaluated.
- `docs/adr/`: decisions already taken, if any. Follow them; propose a new ADR to change one.

## Rules

- **No manual PDFs in the repository.** `data/manuals.yaml` holds the links; PDFs go to `data/pdf/` (ignored). Test fixtures are small PDFs generated by the tests themselves.
- **Secrets only in the environment.** `.env` locally (see `.env.example`), GitHub secrets in CI. Fixtures never hold anything that looks like a key or token: gitleaks fails the PR.
- **One issue, one branch, one PR**, about 400 lines at most, tests first. PR title: `Area: outcome sentence`. Fill in `.github/pull_request_template.md`: at most 150 words, CI checks it. To change a description, rewrite it; never append to it. Push only to your branch.
- **Models are behind one interface.** Answering goes through `llm.complete()`; its backends are the Claude CLI (development, CI) and the Gemini API (demo, reference run). Never call a provider SDK elsewhere.

## Tests

- One test per acceptance criterion of the issue, written first and seen failing.
- Tests go through the public interface and touch real things: a real Postgres with pgvector (the `docker compose` service), real SQL, the real HTTP app. A test that would still pass with the feature broken proves nothing; mocks are for model calls and the network only.

## Checks

The gates are the steps of `.github/workflows/ci.yml` and, for `frontend/`, of `frontend-ci.yml`; run them locally and have them green before opening a PR.

## Agents that build askmystuff

Agents in `.github/workflows/agent-*.yml` build askmystuff from GitHub issues: the coder builds an issue labeled `ready-for-agent` once every issue in its `Blocked by` is closed; when the coder stops with questions, the answerer answers what the sources settle and starts it again (the owner's reply to the rest starts it too); the reviewer reviews each PR; the fixer answers the owner's `@claude`, repairs red CI on `agent/*` branches, and applies the reviewer's `changes needed`. After each merged PR, the learner may propose a rule or a check as an issue labeled `lesson`; the owner accepts it by labeling it `ready-for-agent`. After a second failed review the PR becomes `hard` and Opus takes over; after a third, the agents stop and hand over to the owner. Agents push branches and open PRs; only the owner merges.

How agents work on a PR:

- A PR comment is short: outcome first, then at most 5 short lines or a short checklist. Details go in the commit message or inline comments.
- A review reports only what blocks a merge: at most 5 findings, at most 3 lines per inline comment. Minor points share one non-blocking line.
- A tool you need is on `main` but not on your branch: `git merge origin/main`, then go on. Never rebase, never force-push.

An issue is `hard` when any of these holds; otherwise it is normal:

- it changes what the evaluation measures: the reference questions, a metric, the judge, a CI threshold;
- it designs a prompt the answer or the judge depends on;
- it touches security: secrets, rate limits, the agent or deploy workflows;
- no existing pattern in the code shows how to do it.

| Agent | Normal | `hard` |
|---|---|---|
| Coder | Sonnet 5.5, effort high | Opus 5.5, effort high |
| Answerer (coder's questions) | Sonnet 5.5, effort high | Opus 5.5, effort high |
| Reviewer | Sonnet 5.5, effort medium | Opus 5.5, effort high |
| Fixer (`@claude`) | Sonnet 5.5, effort high | Opus 5.5, effort high |
| Fixer (red CI) | Sonnet 5.5, effort high | Sonnet 5.5, effort high |
| Fixer (review) | 1st failed review: Sonnet 5.5, high | 2nd: Opus 5.5, high, and the PR becomes `hard` |
| Learner (each merged PR) | Sonnet 5.5, effort high | Sonnet 5.5, effort high |

`gh pr edit` may fail on this repository; edit a PR's title or description with `python3 tools/edit_pr.py <n> --title <title> --body-file <file>`. Agents never close or merge a PR: say what blocks you in a PR comment instead.
